📋 Dokumentasi API Department Approval - E-Office ST/SK Dekan

🎯 Overview
Modul Department Approval menangani proses persetujuan dan penandatanganan surat pengantar di tingkat departemen. Flow: Kaprodi review → Admin Prodi draft surat pengantar → Kaprodi sign → Kadep sign (optional) → Forward ke Fakultas.

🌐 Base URL
Local: http://localhost:3079
Network: http://192.168.18.36:3079

🔐 Authentication
- Semua endpoint PRIVATE (perlu login)
- Role yang terlibat: KAPRODI, ADMIN_PRODI, KADEP
- Cookie: better-auth.session_token harus terkirim

⚠️ IMPORTANT: Setelah login, wajib panggil GET /me untuk mendapatkan informasi user lengkap termasuk role.

import { useEffect, useState } from 'react';
import { departmentApprovalService } from '../services/departmentApproval.service';

export const KaprodiQueue = () => {
  const [letters, setLetters] = useState([]);
  const [loading, setLoading] = useState(true);
  const [page, setPage] = useState(1);
  const [totalPages, setTotalPages] = useState(1);

  useEffect(() => {
    loadQueue();
  }, [page]);

  const loadQueue = async () => {
    setLoading(true);
    try {
      const response = await departmentApprovalService.getKaprodiQueue({ page, limit: 10 });
      setLetters(response.data.letters);
      setTotalPages(response.data.pagination.totalPages);
    } catch (err) {
      console.error('Failed to load queue:', err);
    } finally {
      setLoading(false);
    }
  };

  const handleApprove = async (id: string) => {
    const notes = prompt('Catatan (opsional):');
    try {
      await departmentApprovalService.approveSubmission(id, notes || undefined);
      alert('Surat berhasil disetujui');
      loadQueue();
    } catch (err: any) {
      alert(err.response?.data?.message || 'Gagal menyetujui surat');
    }
  };

  const handleReject = async (id: string) => {
    const reason = prompt('Alasan penolakan (wajib):');
    if (!reason || reason.length < 1) {
      alert('Alasan penolakan wajib diisi');
      return;
    }

    try {
      await departmentApprovalService.rejectSubmission(id, reason);
      alert('Surat berhasil ditolak');
      loadQueue();
    } catch (err: any) {
      alert(err.response?.data?.message || 'Gagal menolak surat');
    }
  };

  if (loading) return <div>Loading...</div>;

  return (
    <div>
      <h2>Antrian Persetujuan Kaprodi</h2>
      <table>
        <thead>
          <tr>
            <th>Tanggal</th>
            <th>Pengaju</th>
            <th>Jenis Surat</th>
            <th>Keperluan</th>
            <th>Status</th>
            <th>Aksi</th>
          </tr>
        </thead>
        <tbody>
          {letters.map((letter: any) => (
            <tr key={letter.id}>
              <td>{new Date(letter.submittedAt).toLocaleDateString('id-ID')}</td>
              <td>{letter.submitter.name}</td>
              <td>{letter.letterType.name}</td>
              <td>{letter.submissionValues.keperluan}</td>
              <td>{letter.statusDisplay}</td>
              <td>
                <button onClick={() => window.location.href = `/department-approval/${letter.id}`}>
                  Detail
                </button>
                <button onClick={() => handleApprove(letter.id)}>
                  Setujui
                </button>
                <button onClick={() => handleReject(letter.id)}>
                  Tolak
                </button>
              </td>
            </tr>
          ))}
        </tbody>
      </table>

      {/* Pagination */}
      <div>
        <button disabled={page === 1} onClick={() => setPage(page - 1)}>
          Previous
        </button>
        <span>Page {page} of {totalPages}</span>
        <button disabled={page === totalPages} onClick={() => setPage(page + 1)}>
          Next
        </button>
      </div>
    </div>
  );
};

Status | Error                                          | Solusi
-------+------------------------------------------------+----------------------------------------
400    | Alasan penolakan wajib diisi                   | Isi field reason saat reject

400    | Surat tidak dapat disetujui pada status ini    | Cek status surat, harus SUBMITTED

403    | Hanya KAPRODI yang dapat menyetujui            | Login dengan akun KAPRODI
403    | Hanya ADMIN_PRODI yang dapat membuat draft     | Login dengan akun ADMIN_PRODI
403    | Anda tidak memiliki akses untuk menandatangani | Login dengan akun yang sesuai role
404    | Surat tidak ditemukan                          | ID surat tidak valid
500    | Internal Server Error                          | Cek server logs

🔄 Workflow Flow
═══════════════════════════════════════════════════════════════════════════════

1. MAHASISWA/DOSEN → Submit pengajuan
   Status: SUBMITTED
   Active Role: KAPRODI

2. KAPRODI → Review & Approve
   Endpoint: POST /api/department-approval/:id/approve
   Status: SUBMITTED → KAPRODI_REVIEW
   Active Role: ADMIN_PRODI

3. ADMIN_PRODI → Draft Surat Pengantar
   Endpoint: POST /api/department-approval/:id/draft
   Status: KAPRODI_REVIEW → SURAT_PENGANTAR_DRAFT
   Active Role: ADMIN_PRODI (masih bisa edit)

4. ADMIN_PRODI → Submit Draft untuk TTD
   Endpoint: POST /api/department-approval/:id/submit-draft
   Status: SURAT_PENGANTAR_DRAFT → SURAT_PENGANTAR_REVIEW
   Active Role: KAPRODI (first signer)

5. KAPRODI → Sign Surat Pengantar
   Endpoint: POST /api/department-approval/:id/sign
   Status: SURAT_PENGANTAR_REVIEW (masih sama)
   Active Role: KADEP (if butuhTtdKadep = true)

6. KADEP → Sign Surat Pengantar (jika diperlukan)
   Endpoint: POST /api/department-approval/:id/sign
   Status: SURAT_PENGANTAR_REVIEW → SURAT_PENGANTAR_SIGNED
   Active Role: ADMIN_FAKULTAS

7. Auto Forward → Ke Fakultas
   Status: SURAT_PENGANTAR_SIGNED
   Next Module: Faculty Disposition

Alternative Flow:
- KAPRODI → Reject
  Endpoint: POST /api/department-approval/:id/reject
  Status: SUBMITTED → REJECTED
  Final State

   - /signature-queue → KAPRODI atau KADEP
   - Approve/Reject → Hanya KAPRODI
   - Draft/Submit Draft → Hanya ADMIN_PRODI
   - Sign → KAPRODI atau KADEP (sesuai giliran)

2. **Sequential Signing**:
   - Penandatanganan harus berurutan sesuai order (0, 1, 2, ...)
   - Kaprodi biasanya order 0, Kadep order 1
   - System automatically determines next signer

3. **Draft Behavior**:
   - Admin Prodi bisa save draft berkali-kali
   - Setelah submit-draft, tidak bisa edit lagi
   - Draft content flexible (JSON object)

4. **Status Transitions**:
   - SUBMITTED → KAPRODI_REVIEW (after approve)
   - KAPRODI_REVIEW → SURAT_PENGANTAR_DRAFT (after save draft)
   - SURAT_PENGANTAR_DRAFT → SURAT_PENGANTAR_REVIEW (after submit draft)
   - SURAT_PENGANTAR_REVIEW → SURAT_PENGANTAR_SIGNED (after all signatures)
   - Any status → REJECTED (if rejected by Kaprodi)

5. **Permissions**:
   - Frontend should check permissions from /api/department-approval/:id
   - Show/hide buttons based on canApprove, canReject, canDraft, etc
   - Always validate on backend regardless of frontend checks

6. **Integration with Other Modules**:
   - After SURAT_PENGANTAR_SIGNED → Goes to Faculty Disposition module
   - Uses Signature module for managing saved signatures
   - Original submission from Submission module

7. **Best Practices**:
   - Always show current status and active role to user
   - Confirm before reject/sign actions
   - Show signature progress (who signed, who's next)
   - Preview draft before submitting for signature
   - Log all actions for audit trail
