📄 Dokumentasi API Surat Hasil (SK/ST) - E-Office ST/SK Dekan

🎯 Overview
Modul Surat Hasil menangani proses drafting, verifikasi, dan penandatanganan Surat Keputusan (SK) dan Surat Tugas (ST) oleh tim fakultas. Flow: Staf draft → Supervisor verifikasi → Manajer TU approve → Pejabat (Dekan/Wadek) sign → UPA legalisasi.

Terdapat 2 sub-module:
1. **Surat Hasil** (/api/surat-hasil) - Drafting dan verifikasi oleh Staf/Supervisor/Manajer TU
2. **Signing** (/api/signing) - Penandatanganan oleh Pejabat (Dekan/Wadek)

🌐 Base URL
Local: http://localhost:3079
Network: http://192.168.18.36:3079

🔐 Authentication
- Semua endpoint PRIVATE (perlu login)
- Role yang terlibat: STAF_AKADEMIK, STAF_SUMBER_DAYA, SUPERVISOR_AKADEMIK, SUPERVISOR_SUMBER_DAYA, MANAJER_TU, DEKAN, WAKIL_DEKAN_1, WAKIL_DEKAN_2
- Cookie: better-auth.session_token harus terkirim

⚠️ IMPORTANT: Setelah login, wajib panggil GET /me untuk mendapatkan informasi user lengkap termasuk role.

// services/suratHasil.service.ts
import axios from 'axios';

const api = axios.create({
  baseURL: 'http://localhost:3079',
  withCredentials: true
});

export const suratHasilService = {
  // Get drafting queue
  getDraftingQueue: async (params?: { page?: number; limit?: number; search?: string }) => {
    const response = await api.get('/api/surat-hasil/queue', { params });
    return response.data;
  },

  // Get my drafted letters
  getMyDrafts: async (params?: { page?: number; limit?: number; documentType?: string }) => {
    const response = await api.get('/api/surat-hasil/my-drafts', { params });
    return response.data;
  },

  // Get letter detail
  getLetterDetail: async (id: string) => {
    const response = await api.get(`/api/surat-hasil/${id}`);
    return response.data;
  },

  // Create draft
  createDraft: async (letterId: string, data: {
    documentType: 'SURAT_TUGAS' | 'SURAT_KEPUTUSAN';
    perihal?: string;
    content: Record<string, any>;
    tembusan?: string[];
    signatories: Array<{
      signerRole: string;
      signerName: string;
      signerNip?: string;
      order: number;
    }>;
  }) => {
    const response = await api.post(`/api/surat-hasil/${letterId}/draft`, data);
    return response.data;
  },

  // Update draft
  updateDraft: async (documentId: string, data: {
    content?: Record<string, any>;
    tembusan?: string[];
    perihal?: string;
  }) => {
    const response = await api.put(`/api/surat-hasil/document/${documentId}`, data);
    return response.data;
  },

  // Submit for verification
  submitForVerification: async (letterId: string, targetSupervisor?: 'AKADEMIK' | 'SUMBER_DAYA') => {
    const response = await api.post(`/api/surat-hasil/${letterId}/submit`, { targetSupervisor });
    return response.data;
  },

  // Approve verification
  approveVerification: async (letterId: string, notes?: string) => {
    const response = await api.post(`/api/surat-hasil/${letterId}/approve`, { notes });
    return response.data;
  },

  // Supervisor edit draft
  supervisorEditDraft: async (letterId: string, data: {
    content?: Record<string, any>;
    perihal?: string;
  }) => {
    const response = await api.put(`/api/surat-hasil/${letterId}/supervisor-edit`, data);
    return response.data;
  },

  // Return for revision
  returnForRevision: async (letterId: string, reason: string) => {
    const response = await api.post(`/api/surat-hasil/${letterId}/return`, { reason });
    return response.data;
  },

  // Sign document
  signDocument: async (letterId: string, data: {
    signatureUrl: string;
    signerName: string;
    signerNip?: string;
  }) => {
    const response = await api.post(`/api/surat-hasil/${letterId}/sign`, data);
    return response.data;
  }
};

export const signingService = {
  // Get pending signatures
  getPendingSignatures: async (params?: { page?: number; limit?: number }) => {
    const response = await api.get('/api/signing/pending', { params });
    return response.data;
  },

  // Get signature detail
  getSignatureDetail: async (signatureId: string) => {
    const response = await api.get(`/api/signing/${signatureId}`);
    return response.data;
  },

  // Sign document (advanced with 3 methods)
  signDocument: async (data: {
    signatureId: string;
    letterInstanceId: string;
    method: 'UPLOAD' | 'CANVAS' | 'SAVED';
    savedSignatureId?: string;
    signatureFile?: File;
    saveAsTemplate?: boolean;
    templateAlias?: string;
  }) => {
    const formData = new FormData();
    formData.append('signatureId', data.signatureId);
    formData.append('letterInstanceId', data.letterInstanceId);
    formData.append('method', data.method);
    
    if (data.savedSignatureId) formData.append('savedSignatureId', data.savedSignatureId);
    if (data.signatureFile) formData.append('signatureFile', data.signatureFile);
    if (data.saveAsTemplate !== undefined) formData.append('saveAsTemplate', String(data.saveAsTemplate));
    if (data.templateAlias) formData.append('templateAlias', data.templateAlias);

    const response = await api.post('/api/signing/sign', formData, {
      headers: { 'Content-Type': 'multipart/form-data' }
    });
    return response.data;
  },

  // Generate draft HTML
  generateDraftHtml: async (data: {
    letterInstanceId: string;
    templateHtml: string;
    variables: Record<string, any>;
    tembusan?: Array<{ type: 'TEXT' | 'USER'; value: string; label?: string }>;
  }) => {
    const response = await api.post('/api/signing/generate-draft', data);
    return response.data;
  }
};

  ]);

🔄 Workflow Flow
═══════════════════════════════════════════════════════════════════════════════

1. After FAKULTAS_DISPOSITION → Status: FAKULTAS_DRAFTING
   Active Role: STAF_AKADEMIK or STAF_SUMBER_DAYA

2. STAF → Create Draft
   Endpoint: POST /api/surat-hasil/:id/draft
   Status: FAKULTAS_DRAFTING (still same, draft saved)

3. STAF → Submit for Verification
   Endpoint: POST /api/surat-hasil/:id/submit
   Status: FAKULTAS_DRAFTING → FAKULTAS_VERIFICATION
   Active Role: SUPERVISOR_AKADEMIK or SUPERVISOR_SUMBER_DAYA

4. SUPERVISOR → 3 Options:
   a. Approve → POST /api/surat-hasil/:id/approve
      Status: FAKULTAS_VERIFICATION (still same)
      Active Role: MANAJER_TU
   
   b. Edit Draft → PUT /api/surat-hasil/:id/supervisor-edit
      Status: FAKULTAS_VERIFICATION (still same)
      Can edit and then approve
   
   c. Return → POST /api/surat-hasil/:id/return
      Status: FAKULTAS_VERIFICATION → FAKULTAS_DRAFTING
      Active Role: STAF (back to staff)

5. MANAJER_TU → 3 Options (same as Supervisor):
   a. Approve → POST /api/surat-hasil/:id/approve
      Status: FAKULTAS_VERIFICATION → FAKULTAS_SIGNING
      Active Role: First Signer (DEKAN/WADEK)
   
   b. Edit Draft → PUT /api/surat-hasil/:id/supervisor-edit
      Status: FAKULTAS_VERIFICATION (still same)
   
   c. Return → POST /api/surat-hasil/:id/return
      Status: FAKULTAS_VERIFICATION → FAKULTAS_DRAFTING
      Active Role: STAF

6. PEJABAT → Sign Document
   Endpoint: POST /api/surat-hasil/:id/sign OR POST /api/signing/sign
   Status: FAKULTAS_SIGNING (sequential signing)
   If all signatures complete:
     Status: FAKULTAS_SIGNING → UPA_NUMBERING
     Active Role: UPA

7. UPA → Legalisasi (separate module)

📌 Important Notes
═══════════════════════════════════════════════════════════════════════════════

1. **Two Signing Endpoints**:
   - `/api/surat-hasil/:id/sign` - Simple signing (just URL, name, NIP)
   - `/api/signing/sign` - Advanced signing (3 methods: UPLOAD, CANVAS, SAVED)

2. **Supervisor 3 Options**:
   - Verify → Forward to next role
   - Edit Draft → Modify content then can verify
   - Return → Send back to staff for revision

3. **Sequential Signing**:
   - Signatories must sign in order (0, 1, 2, ...)
   - System tracks currentSignerOrder
   - After all sign → forward to UPA

4. **Draft Flexibility**:
   - Content is flexible JSON (ST vs SK different structure)
   - Frontend should have templates for each type
   - Signatories array defines signing sequence

5. **Saved Signatures Integration**:
   - Pejabat can use saved signatures for faster signing
   - Can save new signature as template during signing
   - Reduces repeated file uploads

6. **Status Transitions**:
   - FAKULTAS_DRAFTING → FAKULTAS_VERIFICATION (after submit)
   - FAKULTAS_VERIFICATION → FAKULTAS_SIGNING (after Manajer TU approve)
   - FAKULTAS_SIGNING → UPA_NUMBERING (after all signatures)
   - FAKULTAS_VERIFICATION → FAKULTAS_DRAFTING (if returned)

7. **Best Practices**:
   - Save draft frequently before submit
   - Preview draft before submitting for verification
   - Use saved signatures for consistency
   - Track signing progress (who signed, who's next)
   - Log all actions for audit trail
